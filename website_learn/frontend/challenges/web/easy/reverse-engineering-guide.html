Introduction

How this guide works

Welcome to the Reverse Engineering intro room! RE is one of the most valuable and satisfying skills in cybersecurity. This guide walks you through every lesson in the lab with full explanations, worked examples, and the exact commands to use. You do not need any prior RE experience — just a terminal and curiosity.

What you will learn: how programs are compiled, how to extract secrets from binaries using strings, how to read assembly with objdump, how to intercept function calls with ltrace, and how to approach any CTF crackme systematically.

Part 1

What is Reverse Engineering?

  • Concept RE is backwards engineering. A developer writes source code, compiles it into a binary, and ships the binary. You receive only the binary. Your job is to reconstruct what the source code did by analysing the binary.
  • Pipeline Source (.c) → Compiler → Assembly (.s) → Assembler → Object (.o) → Linker → Executable (ELF/PE). You start at the right end and work left.
  • Q1 Answer The process is called reverse engineering. Static analysis does not involve running the binary. The stage that converts assembly to machine bytes is the assembler.

Part 2

Finding Hidden Text with strings

  • Step 1 Run strings on the binary. Open a terminal and run:
    strings ./crackme_01
    Scroll through the output looking for readable text like passwords, flags, or URLs.
  • Step 2 Filter with grep. Narrow the output:
    strings ./crackme_01 | grep -i "CTF{\|flag\|pass"
    The -i flag makes the search case-insensitive.
  • Step 3 Show file offsets. Use -t x to print the hex offset of each string — useful when you want to locate it inside a hex editor:
    strings -t x ./crackme_01
  • Answers Tool = strings. Offset flag = -t x. The flag in the simulated output = CTF{str1ngs_4r3_34sy}.

Part 3

Disassembly with objdump & Ghidra

  • Step 1 Disassemble with Intel syntax.
    objdump -d -M intel ./crackme | grep -A 60 "<main>"
    Look for call strcmp — that is where the password comparison happens.
  • Step 2 Understand the jump logic. After strcmp returns, the code checks test eax, eax. If the result is zero (passwords match), the next je (jump if equal) takes you to the success path. If not, jne jumps to the failure path. To "patch" the binary, reverse this jump.
  • Step 3 Open in Ghidra. Import the binary → auto-analyse → navigate to main in the Symbol Tree. The decompiler panel shows readable pseudo-C. Variable names will be auto-generated (e.g. local_48) but the logic is clear.
  • Answers Intel syntax flag = -M intel. Comparison instruction = cmp. Free decompiler = Ghidra.

Part 4

Dynamic Analysis with ltrace & strace

  • Step 1 Run ltrace on the crackme.
    ltrace ./crackme_01
    When the program asks for a password, type anything (e.g. test123). ltrace prints: strcmp("test123", "s3cr3t_p4ss") — the second argument is the real password!
  • Step 2 Run strace for syscall tracing.
    strace -e trace=read,write ./crackme_01
    Filter to only read/write syscalls to see what data the program reads from disk or writes to screen.
  • Step 3 Combine tools. Start with ltrace. If the comparison is obfuscated (no direct strcmp), move to strace, then static disassembly, then Ghidra decompilation.
  • Answers Library call tracer = ltrace. Syscall tracer = strace. Filter flag = -e trace=.

Part 5

Complete CTF Crackme Methodology

  • Step 1 Identify the binary. file ./crackme tells you the architecture (32/64-bit), OS (Linux ELF / Windows PE), and whether debug symbols are stripped.
  • Step 2 strings first, always. strings ./crackme | grep -i "CTF{". A surprising number of beginner challenges embed the flag in plain text.
  • Step 3 ltrace for live strcmp. Most easy crackmes use a direct strcmp. ltrace reveals both arguments — you get the password for free.
  • Step 4 objdump / Ghidra for logic. When the check is more complex (XOR loop, character-by-character), use Ghidra's decompiler to understand the algorithm, then recreate the expected input manually or with a Python script.
  • Answers Binary identification command = file. Runtime XOR pattern = XOR encoding. Binary challenge type = crackme.
