Introduction

What is Web Reconnaissance?

Before any attack, a professional penetration tester performs reconnaissance — passively and actively gathering information about the target. This lab teaches you to map the attack surface using open-source tools without needing Burp Suite.

robots.txt & sitemap.xml

Find what the server is trying to hide

  • Step 1 Launch the target server above, then open its URL in your browser.
  • Step 2 Navigate to /robots.txt — look for any Disallow entries. These are paths the admin is trying to hide from search engines (and accidentally revealing to you).
  • Step 3 Navigate to /sitemap.xml — this gives you a complete map of all URLs the site exposes.
  • Step 4 Note the disallowed path. You will use it in the final CTF step!

Tech Stack Fingerprinting

WhatWeb & Wappalyzer

  • Step 1 Start your Kali container and connect via your host terminal using the displayed command.
  • Step 2 Run WhatWeb against the target:
    whatweb http://host.docker.internal
  • Step 3 For more details, use the verbose flag:
    whatweb -v http://host.docker.internal

Wappalyzer Browser Tool

Conceptual Guide

Wappalyzer is the industry standard for fast, visual technology detection. It is available as a browser extension for Chrome, Firefox, and Edge.

  • Step 1 In a real-world scenario, you would install the extension and click the icon while visiting a site.
  • Step 2 It instantly detects CMS (WordPress, Drupal), Frameworks (React, Vue), and Backend technologies (Node.js, PHP, Flask).
  • Step 3 While we use terminal tools like WhatWeb for this lab, knowing how to use Wappalyzer is crucial for quick reconnaissance during initial discovery.

Directory Fuzzing with ffuf

Discover hidden paths

  • Step 1 Inside your Kali terminal, run this command to fuzz for directories:
    ffuf -u http://host.docker.internal/FUZZ -w /usr/share/wordlists/dirb/common.txt -fc 404
    FUZZ is the placeholder — ffuf replaces it with each word from the wordlist.
  • Step 2 Look for any paths that return HTTP 200 or 301. These are valid endpoints worth investigating.
  • Step 3 Cross-reference your ffuf results with the paths you found in robots.txt. They should match!

Subdomain Enumeration

Virtual host fuzzing

  • Step 1 To discover virtual hosts, fuzz the Host header with ffuf:
    ffuf -u http://host.docker.internal -H "Host: FUZZ.target.local" -w /usr/share/wordlists/dirb/common.txt -fw 1
  • Step 2 The -fw 1 flag filters results by word count, removing identical "not found" responses so only unique results show up.

Connecting the Dots

How to use your findings

At this point, you should have two key pieces of information:

1. From robots.txt: You saw a path like /staging or /admin that the server admin explicitly wants to hide.
2. From ffuf: You ran a fuzzing scan and confirmed that a path (like /staging) actually exists and returns a 200 OK status.

The presence of a "disallowed" path in robots.txt that is confirmed to exist by ffuf is a massive red flag. These are often forgotten development areas or internal portals containing sensitive data — in our case, the CTF Flag.

Capture the Flag

Put it all together

  • Step 1 Use the information you gathered from robots.txt and your ffuf scan to identify the hidden path on the target server.
  • Step 2 Browse directly to that hidden path in your browser while the target server is running. The page will display the flag if you found the correct location.
  • Step 3 Enter the flag you discovered into the final quiz question in the lab to earn your points. The flag follows the CTF{...} format — find it yourself!

Frequently Asked Questions

Why no Burp Suite in this lab?
This lab focuses on command-line OSINT and fuzzing tools that work entirely from the terminal. This is a more realistic workflow when working on remote servers or headless environments.

My ffuf isn't finding anything?
Make sure the target server is running first! Also confirm you are using host.docker.internal as the hostname, not localhost, since you are connecting from inside a Docker container.
