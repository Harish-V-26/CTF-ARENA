Introduction

How the practical labs work

Welcome to the practical side of CTF ARENA! Unlike the beginner quizzes, the Easy Level challenges require you to attack real, running servers. To do this safely, our platform uses Docker to instantly spin up isolated, private lab environments specifically for you.

This guide will teach you the expected workflow for finding the flags in both the DVWA challenge and the Brute Force Target challenge.

Damn Vulnerable Web App (DVWA)

Step-by-step to your first flag

  • Step 1 Launch the Container. Click the red "Launch DVWA Instance" button. Our backend will start a Docker container and give you a unique port. A new tab will open automatically.
  • Step 2 Log in & Setup. Use the default credentials: Username: admin | Password: password. Then, click "Create / Reset Database" at the bottom of the setup page to initialize the app.
  • Step 3 Find the Vulnerability. We need to get the flag! Navigate to the Command Injection tab. This page lets you ping an IP, but it doesn't sanitize input.
  • Step 4 Exploit it. Type 127.0.0.1; ls -la into the box. The semicolon (;) tells Linux to execute a second command after the ping finishes. You should see a list of files.
  • Step 5 Capture the Flag. If you look closely at the files, there isn't a flag.txt in the current directory. However, running commands like 127.0.0.1; cat /etc/passwd proves you have execution. Answer the final questions in the lab correctly to simulate capturing the flag and earning your points!

Brute Force Target

Using Kali Linux & Hydra

  • Step 1 Start the Target. Go to the Brute Force Lab page and click the "Open Target Page" button. You'll see a dark Admin Portal login screen.
  • Step 2 Start the Kali Attack Box. Go back to the lab page and click "Start Kali Container". Our system will launch a private Kali Linux instance for you and display a connection command.
  • Step 3 Connect to Kali. Copy the displayed command (e.g., docker exec -it [id] bash) and paste it into your local computer's terminal. You are now inside Kali!
  • Step 4 Run the Hydra Attack. Since you are attacking the host server from inside a Docker container, you must target host.docker.internal. Run this exact command inside your Kali terminal:
    hydra -l admin -P /usr/share/wordlists/rockyou.txt -f host.docker.internal http-post-form "/api/brute-force-target:username=^USER^&password=^PASS^:Invalid username or password" -s 5000
  • Step 5 Capture the Flag. Hydra will test thousands of passwords. Within seconds, it will find the correct password (qwerty). Go back to the Target Page in your browser, login with admin / qwerty, and the screen will reveal the flag: CTF{...}.

Authentication Basics

Analyzing Login Flows & Decoding JWTs

  • Step 1 Analyze Login Flow. Click "Open Login Portal". In the new tab, open DevTools (F12) and go to the Network tab. Submit the form with incorrect credentials (e.g. test / test). Look at the Network request and notice it returns a 401 Unauthorized status code.
  • Step 2 Successful Login. Clear the Network log. Now log in using the correct credentials provided in the lab (Username: admin | Password: admin123). Observe the Network tab again; the request now returns a 200 OK status code.
  • Step 3 Locate Session Cookies. Now that you are logged in, navigate to the Application tab (Chrome) or Storage tab (Firefox) in your DevTools. Expand "Cookies" and click your domain. You will see two cookies set by the server: session_id and auth_token.
  • Step 4 Decode the JWT Token. Double-click the value of the auth_token cookie and copy the long string. It has three parts separated by dots. Go to jwt.io and paste the token. Look at the decoded JSON payload section—you will clearly see your user data and the secret flag: flag{...}.

Frequently Asked Questions

Why isn't host.docker.internal working?
If you are on Linux, host.docker.internal might not resolve by default. You can try replacing it with your actual computer's local IP address (e.g., 192.168.1.50).

Do I need to stop my containers?
Our backend automatically shuts down your Docker containers when you click the "Stop" buttons or simply close your browser tab! This ensures your computer doesn't run out of memory.
