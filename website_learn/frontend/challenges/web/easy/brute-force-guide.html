Introduction

How the practical labs work

Welcome to the practical side of CTF ARENA! Unlike the beginner quizzes, the Easy Level challenges require you to attack real, running servers. To do this safely, our platform uses Docker to instantly spin up isolated, private lab environments specifically for you.

Brute Force Target

Using Kali Linux & Hydra

  • Step 1 Start the Target. Go to the Brute Force Lab page and click the "Open Target Page" button. You'll see a dark Admin Portal login screen.
  • Step 2 Start the Kali Attack Box. Go back to the lab page and click "Start Kali Container". Our system will launch a private Kali Linux instance for you and display a connection command.
  • Step 3 Connect to Kali. Copy the displayed command (e.g., docker exec -it [id] bash) and paste it into your local computer's terminal. You are now inside Kali!
  • Step 4 Run the Hydra Attack. Since you are attacking the host server from inside a Docker container, you must target host.docker.internal. Run this exact command inside your Kali terminal:
    hydra -l admin -P /usr/share/wordlists/rockyou.txt -f host.docker.internal -s 5000 http-post-form "/api/brute-force-target:username=^USER^&password=^PASS^:Invalid username or password"
    Command Breakdown:
    • hydra: This wakes up the robot program.
    • -l admin: The l (login). We are telling Hydra to only try logging into the account named admin.
    • -P /usr/share/.../rockyou.txt: The P (Password file). We give Hydra a dictionary of passwords to try.
    • -f: The f (fast-exit). Stop the attack immediately once a correct password is found.
    • host.docker.internal: This is the address of the target.
    • -s 5000: The s (server port). Knock on door number 5000.
    • http-post-form: The kind of door it is (a website login form).
    • "/api/...:username=...:Invalid...": This is the map for the door (The URL, the Data format, and the Failure message).
  • Step 5 Login. Hydra will test thousands of passwords. Within seconds, it will find the correct password for the admin user. Go back to the Target Page in your browser, and login using those credentials to reveal the flag.

Frequently Asked Questions

Why isn't host.docker.internal working?
If you are on Linux, host.docker.internal might not resolve by default. You can try replacing it with your actual computer's local IP address (e.g., 192.168.1.50).

Do I need to stop my containers?
Our backend automatically shuts down your Docker containers when you click the "Stop" buttons or simply close your browser tab! This ensures your computer doesn't run out of memory.
