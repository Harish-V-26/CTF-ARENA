Introduction

How the SSRF lab works

Welcome to the SSRF lab! In this module, you will observe how a web server proxies user requests. By feeding the proxy server alternative schemes and bypassed addresses, you can read local server files, circumvent firewalls, and extract sensitive cloud metadata credentials.

Part 1

Basic SSRF & Local File Retrieval

  • Step 1 Log In. Launch the lab and log in using the credentials employee_john / password123.
  • Step 2 Identify Proxy Form. Look at **Tool 1: General Web Previewer**. It performs HTTP requests on behalf of the server.
  • Step 3 Force Local Request. Direct the tool to query a local file on the server's disk using the file URI scheme: file:///flag.txt. The response will reveal the contents of the flag file on disk.

Part 2

Bypassing Firewall Blacklists

  • Step 1 Understand Constraints. Look at **Tool 2: Secure Endpoint Status Checker**. If you supply 127.0.0.1 or localhost, the backend blacklist detects it and blocks the request.
  • Step 2 Use Alternate Representations. Bypassing the blacklist can be accomplished by representing 127.0.0.1 differently:
    Alternative IP: http://127.1/api/admin/config IPv6 Loopback: http://[::1]/api/admin/config Decimal Address: http://2130706433/api/admin/config Hex Address: http://0x7f000001/api/admin/config Bind Address: http://0.0.0.0/api/admin/config
  • Step 3 Extract Second Flag. Submit one of the bypassed URLs into Tool 2. The server will resolve it to the loopback interface, bypass the string matching check, and display the JSON response containing the configuration settings and the secret system flag.

Part 3

Cloud Instance Metadata (IMDSv1)

  • Step 1 Target Cloud IP. In Tool 1, query the link-local metadata address: http://169.254.169.254/latest/meta-data/. You will see a directory listing containing iam/.
  • Step 2 Query IAM Role. Append the path to access the security credentials: http://169.254.169.254/latest/meta-data/iam/security-credentials/. The output will show the attached IAM role name: admin-role.
  • Step 3 Extract Credentials & Flag. Fetch the security credentials of the role: http://169.254.169.254/latest/meta-data/iam/security-credentials/admin-role. The response JSON contains AWS access keys, along with the third flag hidden inside the session token.

Part 4

SSRF Mitigations & IMDSv2

Review the mitigations section in the lesson:

  • Allowlisting: Stricter validation that rejects all protocols and addresses not explicitly permitted.
  • IMDSv2: AWS's defense mechanism which blocks GET-based metadata SSRF attacks by enforcing a PUT request first to get a token.
