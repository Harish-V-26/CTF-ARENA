Introduction

How this multi-vulnerability lab works

Welcome to the OWASP Top 10 Part 1 practical room! In this challenge, you will explore the first 5 vulnerabilities from the OWASP Top 10 list (2025 update). This guide will take you step-by-step through each topic, explaining the exploit methodology to help you retrieve the flags on your own.

Part 1

Broken Access Control (A01:2025)

The objective of this challenge is to perform an Insecure Direct Object Reference (IDOR) to access another user's profile information.

  • Step 1 Launch Target & Go to Profile. Open the target lab and click the Broken Access Control module. This opens /api/owasp-top5-lab/profile?id=101.
  • Step 2 Modify User ID. Change the id parameter in the URL from 101 to 100 and press Enter.
  • Step 3 Find the Flag. Look at the Access Secret field in the profile table of the administrator. Copy the secret flag that starts with flag{...}.

Part 2

Cryptographic Failures (A04:2025)

This challenge demonstrates sensitive data exposure through weak password hashes and deprecated ciphers.

  • Step 1 Open the Database Dump. Click the Cryptographic Failures module. You will be shown a leaked database backup.
  • Step 2 Identify the Hash Algorithm. The admin's password hash is a 32-character hexadecimal digest. Recognize this format to answer the first question.
  • Step 3 Crack the ROT13 Flag. The flag column shows a scrambled ciphertext. Shift the alphabetical characters back by 13 positions (ROT13) using an online decoder (like CyberChef or rot13.com) to reveal the plaintext flag.

Part 3

Injection (A05:2025)

This challenge requires exploiting SQL Injection by inputting a tautology payload that forces the database query to return all rows.

  • Step 1 Go to the User Search Directory. Open the Injection module from the target portal dashboard.
  • Step 2 Submit the Tautology. In the search box, input the classic payload: ' OR '1'='1 and click Search.
  • Step 3 Extract the Flag. The page dumps the full table of users. Look at the last entry for user flag_holder to find and copy the flag.

Part 4

Security Misconfiguration (A02:2025)

This challenge exposes a configuration file backup due to enabled directory browsing.

  • Step 1 Exposed Directory. Access the Security Misconfiguration module, loading `/api/owasp-top5-lab/backup/`.
  • Step 2 Locate the Backup File. Observe that the Apache index directory is fully visible. Open the .bak file shown in the file list.
  • Step 3 Extract the Password. Inside the configuration file, locate the database password value (DB_PASS) to find the flag.

Part 5

Software Supply Chain Failures (A03:2025)

This challenge focuses on vulnerable third-party modules. PyYAML 3.12 is vulnerable to insecure deserialization.

  • Step 1 Identify Dependencies. Open the Software Supply Chain module to fetch the JSON dependency list. The vulnerable library is PyYAML==3.12.
  • Step 2 Find CVE ID. Look up the arbitrary code execution CVE for PyYAML version 3.12. (Format: CVE-YYYY-XXXXX).
  • Step 3 Submit Exploit Payload. Navigate to the deserializer page in the target portal and input the Python execution string: 
    !!python/object/apply:os.system ["echo flag{...}"]
    Click Process YAML to trigger the execution on the server and retrieve the flag.
