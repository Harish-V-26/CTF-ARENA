Introduction

How the CSRF lab works

In this lab, you will explore Cross-Site Request Forgery (CSRF). You will play the role of the attacker, crafting a malicious HTML file that executes a hidden POST request to transfer funds from another user (Bob) to your own account.

Part 1

Executing the CSRF Attack

  • Step 1 Log In. Launch the lab and log in as Alice using the credentials alice / password123. Notice Alice has a starting balance of $1,000.
  • Step 2 Open Attacker Server. Click the yellow Attacker Server button in the top navigation bar. This simulates a server owned and controlled by the attacker.
  • Step 3 Craft Exploit HTML. Write HTML code containing a form that targets the bank's vulnerable transfer endpoint (/transfer) and submits it automatically using JavaScript.
    <form id="csrf-form" action="/transfer" method="POST"> <input type="hidden" name="to_account" value="alice"> <input type="hidden" name="amount" value="2000"> </form> <script> document.getElementById("csrf-form").submit(); </script>
  • Step 4 Deliver and Exploit. Click Save and Host Exploit. Copy the generated exploit URL. Navigate to the Report to Victim page, paste the URL, and submit. The simulated admin bot (Bob) will visit the link.
  • Step 5 Claim Flag. Check the terminal console for success logs. Return to the main bank dashboard and refresh. Alice's balance is now $3,000, and the flag CTF{CSRF_Tr4nsf3r_Succ3ss} will be shown in a green banner.

Part 2

Bypassing Secure Transfer

In Lesson 3, you are tasked with testing the bank's secure transfer endpoint. This endpoint implements secret anti-CSRF tokens to prevent request forgery.

  • Step 1 Inspect Secure Tab. Return to the Bank Dashboard and view the Secure (Token) tab. Notice a unique token value is appended as a hidden parameter.
  • Step 2 Modify Exploit. Go to the Exploit Server. Change the form action to point to /secure_transfer. Save the exploit.
  • Step 3 Test and Fail. Send the new exploit URL to the Victim Bot. The bot logs will show that the bank rejected the transaction with a CSRF Token Mismatch error because the attacker's page cannot guess or read Bob's secret session token.
